# Chat Context Exporter

**Chat Context Exporter** — расширение для Chromium-браузеров, которое локально экспортирует историю диалогов с AI-ассистентами из уже доступного пользователю DOM страницы.

Текущая версия: **0.2.1**.

## Основной принцип

Проект намеренно построен как **DOM-only / network-passive collector**.

Расширение работает только с тем содержимым, которое веб-приложение уже показывает пользователю в браузере. Оно может прокручивать существующий контейнер диалога, ждать штатной подгрузки интерфейса, читать появившиеся DOM-элементы и локально формировать файл экспорта.

Расширение **не**:

- выполняет собственные запросы к API AI-сервиса;
- вызывает закрытые или недокументированные endpoints для получения истории;
- перехватывает и не подменяет `fetch`, `XMLHttpRequest` или `WebSocket`;
- извлекает access token, session token, cookie или другие учетные данные для самостоятельных запросов;
- модифицирует сетевые запросы веб-приложения;
- внедряется во внутреннюю сетевую логику чата;
- пытается обходить Same-Origin Policy, CSP или ограничения доступа к iframe;
- отправляет содержимое экспортируемого диалога разработчику или на сторонний сервер.

Для запуска Chrome штатно выполняет content scripts расширения в контексте вкладки и добавляет локальную плавающую панель управления. Это используется только для чтения DOM, прокрутки и отображения статуса; сетевой слой AI-сервиса не перехватывается и не модифицируется.

Если обычная прокрутка заставляет сам сайт подгрузить более ранние или более поздние элементы истории, такой сетевой обмен выполняет само веб-приложение. Chat Context Exporter не формирует эти запросы и не использует их содержимое напрямую.

## Предупреждение об условиях использования сервисов

DOM-only архитектура не означает, что автоматизированный сбор разрешен правилами каждого AI-сервиса.

У отдельных сервисов условия использования могут ограничивать автоматизацию, scraping, массовый сбор данных или автоматическое взаимодействие с интерфейсом. Сервисы также могут применять ограничения к аккаунтам, если считают конкретное поведение нарушением своих правил.

Перед использованием расширения пользователь должен самостоятельно проверить актуальные условия использования, политики и ограничения конкретного сервиса. Используйте расширение только для диалогов и аккаунтов, к которым у вас есть законный и разрешенный доступ.

Особую осторожность следует проявлять с экспортерами, которые перехватывают сетевой трафик, извлекают токены, вызывают частные API или самостоятельно отправляют запросы к серверу чата. Chat Context Exporter принципиально не использует такие методы.

Использование расширения осуществляется пользователем на свой риск. Проект не гарантирует, что автоматизированная работа с DOM разрешена правилами каждого поддерживаемого или потенциально поддерживаемого сервиса.

## Конфиденциальность

Обработка истории диалога выполняется локально в браузере.

Проект не содержит собственного сервера сбора телеметрии и не передает экспортируемый текст разработчику или сторонним сервисам.

Настройки расширения хранятся локально через `chrome.storage.local`.

При включенной опции технического лога создается локальный TXT-файл. В него записываются диагностические данные работы расширения, включая название страницы, URL страницы без query/hash, выбранный адаптер, параметры прокрутки, счетчики, длительность и ошибки. Текст диалога в технический лог намеренно не копируется.

Подробности: [PRIVACY.md](PRIVACY.md).

## Поддерживаемые ассистенты

### Grok

В версии 0.1.9 адаптер Grok является первой зафиксированной baseline-реализацией.

Поддерживается:

- автоматическое определение Grok по DOM-признакам;
- поиск специализированного scroll-контейнера;
- проход от текущей позиции к началу истории;
- подтверждение начала и конца истории по DOM-маркерам Grok;
- сбор сообщений при движении вверх и вниз;
- дедупликация по стабильным идентификаторам;
- дополнительные проверочные проходы от 1 до 3;
- структурный разбор форматирования ответа;
- экспорт в Markdown;
- автоматическое сохранение или ручное `Сохранить как`;
- технический TXT-лог;
- таймер, прогресс и пользовательские статусы.

### DeepSeek

В версии 0.2.1 адаптер DeepSeek зафиксирован как готовая DOM-only реализация. Проверены запуск из частично загруженной истории, штатная подгрузка старых сообщений самим интерфейсом DeepSeek при прокрутке, виртуализация DOM, накопительный сбор сообщений, дедупликация, один и несколько проходов, ручное и автоматическое сохранение.

Поддерживается:

- автоматическое определение DeepSeek по hostname и DOM-признакам;
- специализированный `.ds-virtual-list` scroll-контейнер;
- сбор виртуализированных элементов по `data-virtual-list-item-key`;
- накопление сообщений во время движения вверх и вниз, даже если DeepSeek затем удаляет ранее видимые элементы из DOM;
- разделение ролей пользователя и ассистента по DOM;
- экспорт только финального `.ds-assistant-message-main-content` без reasoning/search UI из `.ds-think-content`;
- подтверждение начала и конца истории по физической позиции, стабильности `scrollHeight` и стабильности набора видимых virtual-list ключей;
- дополнительные проверочные проходы без дублирования уже собранных сообщений;
- структурный Markdown-экспорт, ручное и автоматическое сохранение, технический лог.

На контрольном тесте DeepSeek расширение стартовало с четырьмя доступными DOM-сообщениями, по мере штатной прокрутки собрало полную историю из 16 сообщений и сохранило идентичный результат в ручном и автоматическом режимах. Дополнительный проход дал прирост `0`, что подтвердило дедупликацию и полноту первого прохода для этого теста.

Для неподдерживаемых сайтов присутствует универсальный fallback поиска прокручиваемого контейнера, но полноценный экспорт сообщений гарантируется только проверенными адаптерами конкретных сервисов.

## Формат Markdown

Название страницы становится H1 документа:

```md
# Название диалога
```

Роли не используются как заголовки и поэтому не смешиваются с иерархией содержимого ответа:

```md
**Пользователь**

Текст сообщения.

---

**Ассистент**

Текст ответа.

## Заголовок внутри ответа
```

При наличии соответствующей структуры в DOM сохраняются:

- заголовки;
- абзацы;
- жирное и курсивное начертание;
- зачеркнутый текст GFM;
- inline code;
- fenced code blocks и язык блока, если его можно надежно определить;
- маркированные и нумерованные списки;
- вложенные списки;
- цитаты;
- ссылки;
- таблицы GFM;
- горизонтальные разделители.

Внешний вид итогового файла зависит от Markdown renderer. Экспорт сохраняет семантическую структуру, а не CSS, шрифты и пиксельные размеры исходного сайта.

## Имя файла

Имя итогового файла формируется из `document.title` страницы.

Например:

```text
Chrome extension: scrape chat history - Grok
```

на Windows будет сохранено как:

```text
Chrome extension - scrape chat history - Grok.md
```

Символы, запрещенные в именах файлов Windows (`< > : " / \\ | ? *`), управляющие символы, опасные окончания и зарезервированные системные имена санитизируются.

При повторном автосохранении используется `conflictAction: uniquify`, поэтому браузер может добавить суффикс к имени.

## Настройки

Значения по умолчанию:

- `Автосохранение` — включено;
- `Сохранять лог` — выключено;
- `Закрывать панель после сохранения` — включено;
- `Дополнительные проходы` — выключены;
- количество дополнительных проходов — `1`, допустимо `1–3`;
- минимальная задержка прокрутки — `100 мс`;
- максимальная задержка прокрутки — `1000 мс`.

Настройки применяются и сохраняются автоматически. Кнопка `По умолчанию` возвращает исходные значения.

### Дополнительные проходы

Один основной проход состоит из движения к началу истории и последующего движения к концу с постоянным сбором DOM-сообщений.

Если включены дополнительные проходы, используется тот же Collector: уже известные сообщения не дублируются, новые сообщения добавляются, а более полный DOM-снимок существующей записи может заменить менее полный.

Максимальная конфигурация — один основной и три дополнительных прохода, то есть четыре полных прохода истории.

## Сохранение

При включенном автосохранении итоговый файл сохраняется через `chrome.downloads` без диалога выбора места. Используется каталог загрузок, настроенный самим браузером пользователя; абсолютный путь к Downloads в расширении не зашит.

При выключенном автосохранении после завершения сбора доступны кнопки `Сохранить` и `Отмена`. `Сохранить` вызывает штатный браузерный диалог выбора имени и места (`saveAs: true`).

Технический TXT-лог, если включен, всегда сохраняется автоматически в каталог загрузок браузера и не вызывает диалог выбора места.

## Установка из исходников

1. Скачайте или клонируйте репозиторий.
2. Откройте `chrome://extensions` в Chromium-браузере.
3. Включите `Режим разработчика`.
4. Нажмите `Загрузить распакованное расширение`.
5. Выберите каталог, в котором находится `manifest.json`.
6. Откройте поддерживаемый чат и нажмите ЛКМ по иконке Chat Context Exporter.

## Разрешения расширения

В `manifest.json` используются только:

- `activeTab` — доступ к текущей вкладке после явного действия пользователя;
- `scripting` — запуск локальных content scripts в активной вкладке;
- `storage` — локальное хранение настроек;
- `downloads` — локальное сохранение экспортов и технического лога.

`host_permissions` не используются.

Принцип разделения:

```text
Site Adapter
    -> Collector
    -> структурированная модель сообщения
    -> Exporter
    -> локальный файл
```

Специфика конкретного AI-сервиса должна находиться в отдельном адаптере. Общие алгоритмы прокрутки, логирования, интерфейса и экспорта не должны содержать наборы селекторов всех сервисов одновременно.

## Правила разработки

Ключевое архитектурное ограничение проекта: поддержка нового сайта не должна добавлять сетевой способ получения истории.

Вклад, который требует перехвата запросов, извлечения токенов, обращения к частным API или обхода браузерных ограничений доступа, не соответствует целям проекта.

Подробнее: [CONTRIBUTING.md](CONTRIBUTING.md). Пошаговая схема подключения следующего сервиса: [ADAPTER_GUIDE.md](ADAPTER_GUIDE.md).

## Известные ограничения

- Grok (0.1.9) и DeepSeek (0.2.1) зафиксированы как проверенные DOM-only адаптеры; изменение DOM соответствующего сервиса в будущем может потребовать обновления адаптера.
- Полнота DOM-only экспорта зависит от того, какие элементы сайт успевает отрисовать при прокрутке.
- Дополнительные проходы уменьшают вероятность пропуска элементов, но не могут дать абсолютную гарантию полноты на любом будущем интерфейсе.
- Timestamp сообщения экспортируется только если адаптер может надежно получить его из доступного DOM; время не угадывается и не запрашивается из API.
- Изображения, вложения и специализированный математический DOM пока не имеют отдельных семантических конвертеров.
- Изменение DOM сайта может потребовать обновления соответствующего адаптера.
