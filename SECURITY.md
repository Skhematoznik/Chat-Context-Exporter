# Безопасность

## Что считается проблемой безопасности

Особенно важны сообщения о случаях, когда расширение:

- может непреднамеренно передать содержимое диалога по сети;
- может прочитать или сохранить учетные данные, не необходимые для заявленной функции;
- выполняет код вне ожидаемого DOM-only сценария;
- сохраняет чувствительные данные в технический лог вопреки документации;
- позволяет странице управлять именем или содержимым файла небезопасным способом;
- имеет чрезмерные разрешения Chrome Extension.

## Как сообщить

Если в репозитории включен GitHub Private Vulnerability Reporting, используйте его для сообщений, содержащих чувствительные технические детали.

Если приватный канал недоступен, создайте Issue с минимальным воспроизводимым описанием, но не публикуйте токены, cookie, личные диалоги или иные секреты.

## Архитектурная граница безопасности

Проект не должен получать историю чата через самостоятельные API-запросы, перехват сетевого слоя или использование токенов пользователя.

Изменение, которое нарушает эту границу, рассматривается не как обычное расширение функциональности, а как изменение модели безопасности проекта.
