# Оформление единственного публикационного коммита — версия 1.0

Цель: один коммит исходников для baseline 1.0, один Git tag `v1.0` и один GitHub Release **1.0**. Никакие кандидаты `rc` и дополнительные версии не публикуются.

## До единственного push

- [ ] Сверить текущее состояние локального Git-репозитория с подготовленным архивом. Не удалять незнакомые локальные изменения автоматически.
- [ ] Убедиться, что `manifest.json` лежит в корне репозитория и каталога устанавливаемого расширения.
- [ ] Убедиться, что manifest `version` и `version_name`, а также runtime version — ровно `1.0`.
- [ ] Убедиться, что обновленный README включает будущее TXT/HTML/PDF без гарантий, правила платформ, предупреждение debugger, ручную установку.
- [ ] Проверить `node --check` для всего JavaScript, валидность `manifest.json`, структуру ZIP, SHA-256 и отсутствие токенов, cookies, приватных данных или временных артефактов.
- [ ] Подтвердить acceptance на реальном Chrome по поддерживаемым адаптерам и режимам; если свежие smoke-тесты для 1.0 еще не делались, не объявлять их проведенными.
- [ ] Убедиться, что user-facing настройка технического лога и повторного прохода по умолчанию выключена.
- [ ] Убедиться, что public Issues включены и работает шаблон `.github/ISSUE_TEMPLATE/bug_report.yml`.

## Один коммит, один tag, один release

1. Поместить содержимое архива **в корень существующего локального репозитория**, не создавать внутри репозитория дополнительную обертку-каталог.
2. Проверить `git status` и `git diff`; создать **один** коммит, например `release: establish Chat Context Exporter 1.0 baseline`.
3. Сделать push в `main` только после финальной проверки и подтверждения.
4. Поставить аннотированный тег **`v1.0`** на этот же commit, отправить tag.
5. Создать **один** GitHub Release `1.0` из тега `v1.0`; загрузить архив `Chat-Context-Exporter-1.0.zip` и `SHA256SUMS.txt` как отдельные Assets. Отметить *Set as latest release*, не включать *pre-release*.
6. Зафиксировать идентичный принятый source tree в Development/Baseline/ как baseline `1.0`; GitHub/source/archive version должны совпадать.

Ветка `main`, тег `v1.0`, исходный baseline и архив должны однозначно относиться к одному проверенному состоянию исходников.
