# Contributing

## Архитектурная граница

Проект допускает два acquisition-механизма:

1. passive CDP Network capture для мигрированных сервисов;
2. DOM collector для сервисов, которые еще не мигрированы или реально требуют DOM-driven lazy loading.

Network capture не должен превращаться в API client. Нельзя выполнять собственные backend-запросы, извлекать credentials, модифицировать traffic или monkey-patch network APIs страницы.

## Перед изменением компонента

Сначала принять решение:

- `PATCH EXISTING`, если предметная область компонента сохраняется;
- `REBUILD COMPONENT`, если меняется его фундаментальный способ работы.

Не сохранять старую реализацию рядом с новой "на всякий случай". История доступна через Git.

## Адаптер

Перед кодированием собрать реальные образцы network/DOM поведения и определить:

- источник данных;
- критерий полноты;
- стабильные ID;
- порядок;
- роли;
- transient/control элементы;
- вложения;
- нужен ли scroll.

Не добавлять абстракции для гипотетических сервисов без текущего использования.

## Проверки

Перед кандидатом:

- `node --check` для всех JavaScript;
- валидный `manifest.json`;
- только обоснованные permissions;
- отсутствие новых `host_permissions`, если они отдельно не требуются;
- отсутствие собственных `fetch` / `XMLHttpRequest` к backend AI-сервисов;
- ZIP integrity;
- targeted harness для измененного адаптера;
- проверка, что неиспользуемые templates/old adapters отсутствуют.
