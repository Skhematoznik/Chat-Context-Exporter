# Руководство по добавлению нового адаптера

Chat Context Exporter подключает каждый AI-сервис отдельным DOM-only адаптером. Общие Collector, Scroller, UI, логирование и exporters не должны превращаться в набор site-specific селекторов.

## Неприкосновенная граница

Новый адаптер может только читать DOM текущей страницы, прокручивать существующий контейнер диалога и ждать штатной реакции интерфейса. Запрещены собственные запросы к backend AI-сервиса, частные API, перехват или подмена `fetch` / `XMLHttpRequest` / `WebSocket`, извлечение токенов и обход браузерных ограничений доступа.

## Версионирование

Новый сервис начинает новую minor-ветку. После DeepSeek `0.2.x` следующий сервис начинается с `0.3.0`. Исправления и последовательные тестовые кандидаты увеличивают patch: `0.3.1`, `0.3.2` и так далее. Суффиксы `candidate` и `baseline` допустимы в имени тестового ZIP или GitHub-артефакта, но не в имени или версии установленного расширения.

## Поэтапная схема

1. Сохранить DOM-примеры как минимум для начала и конца диалога. Если интерфейс виртуализирован, полезен также снимок из середины длинной истории.
2. Создать отдельный `src/adapters/<service>-adapter.js`. На первом этапе реализовать только уверенное определение сервиса, выбор scroll-контейнера и диагностические признаки границ.
3. Запустить один чистый проход с техническим логом и проверить фактическое направление прокрутки, изменение `scrollHeight`, поведение виртуализации и признаки настоящего начала/конца.
4. Добавить стабильные ID, порядок сообщений, роли и content root. Собирать сообщения на каждом шаге в обе стороны, не откладывая чтение DOM до конца прохода.
5. Проверить lazy loading/virtualization на истории, которая при старте загружена не полностью. Collector должен сохранять уже увиденное после удаления DOM-узлов виртуализатором.
6. Проверить Markdown на реальном форматированном ответе: заголовки, списки, ссылки, таблицы, code blocks и скрытый служебный UI. Site-specific исправления вносить в адаптер, общие семантические правила — в общий rich-text parser.
7. Проверить автосохранение, ручной `Save As`, остановку, дополнительные проходы и отсутствие дублей.
8. Только после успешных логов зафиксировать адаптер как готовый и перенести его версию в Baseline.

## Минимальный контракт адаптера

Адаптер должен предоставлять:

- `id` и `displayName`;
- `detect()`;
- `findScroller()`;
- `getVisibleMessages()`;
- `getMessageId()`;
- `getMessageOrderKey()`;
- `getMessageRole()`;
- `getMessageContentRoot()`;
- при наличии надежного DOM-времени — `getMessageTimestamp()`;
- `getHistoryStartState()` и `getHistoryEndState()`.

Граница считается надежной не по одному случайному признаку. Предпочтительно сочетать физическую позицию scroll-контейнера, site-specific DOM-маркер и стабилизацию высоты/набора виртуализированных элементов.

## Проверки перед выдачей кандидата

- `node --check` для каждого JavaScript-файла;
- валидный `manifest.json`;
- отсутствие `host_permissions`;
- поиск запрещенных сетевых примитивов в исходниках;
- `unzip -t` для итогового ZIP;
- отдельная проверка, что уже готовые адаптеры Grok и DeepSeek не изменены без необходимости.
