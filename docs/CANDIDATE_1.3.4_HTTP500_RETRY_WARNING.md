# Кандидат 1.3.4 — восстановление после HTTP 500

**Исходная версия:** кандидат 1.3.3. **Stable baseline:** 1.2, не изменяется.

## Основание

Журнал `№ 8 AWF` от 2026-10-18: основной проход 22/22 страниц (212 сообщений), начало истории достигнуто; дополнительный проход получил 3 страницы, запрос четвёртой (`before=47979afd-…`) через ~30,5 с получил `HTTP 500`. Кандидат 1.3.3 отбросил дополнительный проход и правильно сохранил полный первый, но предупредил «Экспорт не создан: история неполная» внутри причины.

## Алгоритм

1. Применяется только к `HTTP 500` на **ожидаемом** сетевом запросе авторизованного ChatGPT thread (страница текущего курсора). Отказы на нерелевантных запросах игнорируются.
2. На первом 500 в текущем проходе фиксируется ошибка, принятые страницы остаются в памяти. Устанавливается `waiting-http-retry`, `httpRetryStatus=500`, срок ожидания.
3. Выдерживается минимум 30 секунд. `Retry-After` учитывается, если меньше либо равен 5 минутам; при значении более 5 минут не делается автоматической перезагрузки. Пользователь может отменить ожидание.
4. По завершении паузы выполняется **единственный** `Page.reload` текущего прохода. Принятые страницы повторно сверяются по курсорной цепочке и содержимому. Совпавшие не добавляются повторно, затем загружаются недостающие.
5. Разрешено обновление только первой (tail) страницы при прежней курсорной идентичности, аналогично существующей 429-защите. Историческое несоответствие вызывает `HTTP_500_CHECKPOINT_MISMATCH`, без небезопасного объединения.
6. Повторный 500 завершает текущий проход. Если основной проход неполон — итоговый `.md` не сохраняется. Если завершённый первый проход уже есть, частичный дополнительный отбрасывается, а первый сохраняется с корректным предупреждением.

Сетевой захват остаётся пассивным: нет собственных backend запросов, перехвата, подмены сетевых ответов, бесконечных reload.

## Проверки

Запуск `node --test tests/*.test.js`, `node --check` для JS; сверка архива установки, исходного ZIP и SHA-256. Сценарии: 500 после нескольких страниц, целостный replay до `hasPreviousPage=false`, `Retry-After`, запрет второго повтора, mismatch исторической страницы, fallback после полного основного прохода, первая страница без checkpoint, отмена во время паузы, игнорирование посторонних 500. Предыдущие тесты HTTP 403 и 429 сохраняются.
