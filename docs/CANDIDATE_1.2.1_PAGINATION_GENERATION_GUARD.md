# Chat Context Exporter 1.2.1 — контроль генерации и пагинации ChatGPT

**Статус:** CANDIDATE / БРАУЗЕРНАЯ ПРИЕМКА ОЖИДАЕТСЯ. Исправление дефектов кандидата 1.2. Основа: весь source-пакет кандидата 1.2, включая 1.1 (HTTP 403) и 1.2 (DIL→Markdown). Публичный baseline 1.0 не изменён.

## Исходные наблюдения

- Два неудачных экспорта версии 1.2 завершились `response-timeout`; первые две страницы получены (`HTTP 200`), затем ответ с `before=56772551…` не соответствовал ожидаемому `before=5b065d59…`.
- Оператор предоставил шесть последовательных JSON-снимков страницы истории: 1 + 1 + каскад из четырёх после одной прокрутки. Страница способна приходить до того, как расширение включило очередное ожидание.
- HTML-снимок во время незавершенного ответа содержит активную кнопку `<button aria-label="Остановить">`; после завершения без доставки ответа видна ошибка и кнопка «Повторить». Наличие ответа JSON первой страницы ещё не означает, что чат стабилизировался.
- Скриншоты показывали HTTP 429 от ChatGPT. Его причины установить нельзя; расширение не пытается обходить ограничение.

## Поведение 1.2.1

1. **Перед первым захватом:** только для обычного ChatGPT Thread отслеживается наличие активной кнопки Stop. Старт откладывается до её исчезновения и 1800 мс устойчивой паузы. Максимальное ожидание — 180000 мс, отмена через панель доступна. Никаких кликов Stop/«Повторить».
2. **После обычного reload:** контент-скрипт не начинает прокрутку, пока кнопка Stop активна. Если зафиксирована генерация после reload и она закончилась, повторно загружается текущая вкладка **один раз за проход** и захват текущего прохода начинается с tail; ранее принятые страницы того же прохода сбрасываются. При повторной генерации после нового reload выводится ясная ошибка; бесконечного цикла нет.
3. **Каскадная пагинация:** CDP listener продолжает наблюдать сетевые ответы в состояниях `capturing` и `awaiting-scroll`, хранит до 24 страниц / 24 MiB (лимит по длине исходного тела), связывает по `requestBefore = previous.startCursor`, проверяет дубли. Даже если страница пришла до начального tail, она может быть собрана позднее.
4. **Неполная история:** при наличии опережающих страниц и отсутствии ожидаемой промежуточной страницы через 15 с — ошибка `CURSOR_CHAIN_INCOMPLETE`. В логе записываются ожидаемый и буферизованные курсоры, число принятых страниц. Неполный MD не сохраняется.
5. **Отключение:** при ошибке/отмене таймеры и буфер очищаются, debugger отключается. При ожидании Stop до подключения debugger отмена безопасна.

Все действия с сетью остаются **пассивными**: `chrome.debugger` наблюдает штатные браузерные `fetch`-ответы; `Page.reload` — штатная перезагрузка; расширение не посылает собственных HTTP-запросов к ChatGPT и не использует cookies/tokens для доступа.

## Проверки

`node --test tests/*.test.js`: **28/28 PASS** после создания кандидата. Сохранены прежние 18 проверок и добавлены 10 новых тестов (буфер страниц, сохранение порядка, недостающее звено, дубли, Stop, короткий чат ready, отмена и сброс текущего прохода).

Шесть обезличенных маркеров курсоров в `tests/fixtures/chatgpt-cursor-chain.json` представляют последовательность и количество исходных записей из предоставленных JSON; сами пользовательские сообщения, приватные идентификаторы и HTML-страницы не включены в пакет.

Ограничения: клиентский тест не заменяет установку в Chrome. Реальный эффект восстановления при тяжёлой серверной нагрузке HTTP 429/403 не доказан до браузерной приемки. Восстановление отсутствующей средней страницы не возможно без её штатного получения от интерфейса; экспортер корректно прекращает работу, не создавая неполный файл.

## Браузерная приёмка

1. Отключить 1.0/1.1/1.2 в Chrome, загрузить распакованный установочный 1.2.1 из отдельного каталога.
2. **Активная генерация:** начать экспорт, пока активна кнопка Stop. Проверить сообщение ожидания, отсутствие прокрутки, запуск только после исчезновения Stop. Отдельно проверить отмену через панель.
3. **Возобновившаяся после reload генерация:** если ChatGPT самостоятельно возобновил ответ, проверить один повтор захвата после стабилизации, без цикла reload.
4. **Длинный `№ 7 AWF`:** с сохранением технического лога пройти всю историю; проверить буферизацию и принятие каскада, отсутствие `cursor-chain-mismatch`, подтверждённые `startReached`, `tailReached`, `cursorChainComplete` и корректный MD.
5. Если сервер вернул 403/429 или промежуточная страница не поступила, убедиться в диагностике и отсутствии неполного `.md`. Приложить журнал без конфиденциальных данных.

**Решение:** до браузерной приемки кандидат 1.2.1 не переводится в baseline и не публикуется в GitHub.
