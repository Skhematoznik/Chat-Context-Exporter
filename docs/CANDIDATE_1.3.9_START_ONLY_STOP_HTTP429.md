# Candidate 1.3.9 — запуск Stop только один раз и немедленный HTTP 429 restart

**Источник:** Candidate 1.3.8; стабильный Baseline 1.2 и GitHub не изменены. Статус: `BROWSER_ACCEPTANCE_PENDING`.

## Алгоритм

1. Пользователь нажимает «Экспорт». Только в этот момент проверить видимую Stop.
2. Если Stop была активна, ждать её исчезновения до `generationWaitSeconds` (30–3600 с); если не была активна, сразу перейти дальше.
3. Зафиксировать доступный последний ответ до первоначальной перезагрузки (DOM-tail при плашке максимальной длины обсуждения).
4. Подключить пассивное наблюдение `chrome.debugger` и выполнить штатную перезагрузку. Игнорировать новые Stop после старта, даже если они присутствуют после reload.
5. Получить начальную страницу JSON истории. Прокручивать вверх, инициируя запросы `/messages?before=...`; принимать только непрерывную цепочку курсоров. Ни появление Stop, ни `scrollTop=0` не являются основанием остановить пагинацию.
6. При HTTP 429 **на необходимой странице** выполнить немедленный reload и повторить весь текущий проход с начальной страницы. Каждый restart очищает неполные данные этого прохода; полностью завершённые предыдущие проходы не трогает. Всего допускается **пять** повторных запусков, на шестом 429 — error или fallback на ранее завершённый первый проход.
7. Только после `hasPreviousPage=false` и подтверждённой цепочки возможны `PASS_COMPLETED`, дополнительный проход и сохранение Markdown.

**Ограничение:** повторные запросы начальной страницы, не относящиеся к ожидаемому курсору, в том числе их HTTP 429, не должны перезапускать актуальную цепочку. Немедленный reload не выполняет собственный API-запрос, но вызывает штатные запросы ChatGPT. `Retry-After` умышленно не применяется в этом кандидате по требованию оператора; это может ухудшить rate limit.

## Проверки

- Проверено статически отсутствие вызовов ожидания Stop после начала capture и внутри пагинации.
- Проверены пять немедленных restart, отказ на шестом 429, сохранение полного первого прохода при неудаче дополнительного, отсутствие дублей, отмена перед restart, непрерывность курсоров, отсутствие смешивания принятых страниц из разных попыток.
- JS syntax, автоматизированные тесты, структура ZIP, SHA-256 — см. итоговый TAP и файл SHA256SUMS.
- **Реальная браузерная приёмка не выполнена:** нужно проверить оба исходных состояния страницы («плашка лимита», активная Stop) и фактическое HTTP 429.

## Ожидаемые сигналы лога

- Только при активной Stop в момент запуска: `CHATGPT_INITIAL_STOP_ACTIVE`, затем `CHATGPT_GENERATION_GUARD_STARTED | phase=before-start`.
- При восстановлении 429: `CHATGPT_THREAD_HTTP_429_RETRY_SCHEDULED | delayMs=0; maxRetries=5`, `CHATGPT_THREAD_HTTP_429_RETRY_STARTED`, `PAGE_RELOAD_REQUESTED | reason=http-429-immediate-restart`.
- Успех: `CHATGPT_THREAD_START_REACHED`, `PASS_COMPLETED`, `CAPTURE_READY`, сохранение Markdown.
- Не должно быть `CHATGPT_GENERATION_GUARD_STARTED | phase=after-reload` или `phase=before-scroll`.
