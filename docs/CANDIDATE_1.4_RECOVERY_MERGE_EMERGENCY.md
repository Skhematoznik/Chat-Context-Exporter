# Candidate 1.4 — recovery, merge, emergency DOM-tail

Состояние: `CANDIDATE / BROWSER ACCEPTANCE PENDING`; основа: полный кандидат `1.3.9`; стабильный baseline остаётся `1.2`.

## Сценарии запуска

1. Видимая активная **Stop при нажатии** → ожидание исчезновения (настройка `generationWaitSeconds`) → pre-reload DOM-tail, если есть плашка лимита → reload → пассивная пагинация. Любая **последующая** Stop игнорируется.
2. Плашка **максимальной длины** при запуске → обязательный захват user + assistant Markdown из DOM до reload → если не вышло, **не** перезагружать и показать инструкцию ручного сохранения → иначе reload → сбор истории.
3. Плашка **ошибки доставки** при запуске → reload → сбор доступной истории; Stop после reload игнорируется. Последний ответ помечается неподтверждённым там, где факт ошибки доставки достоверно зарегистрирован.
4. Обычный чат без всех трёх признаков → reload → сбор истории.

## Восстановление

- При HTTP 403, 429, 500 **на ожидаемом запросе** → ожидание `attempt × errorRetryBaseSeconds` → reload → заново текущий проход.
- При отсутствии ответа в watchdog, истечении ожидания пропущенного cursor, повторном cursor без продвижения и исчерпании шагов прокрутки → тот же общий budget попыток.
- Базовая задержка `1–60` секунд (по умолчанию 5); количество повторов `1–10` (по умолчанию 5). Паузы по умолчанию `5, 10, 15, 20, 25` секунд = 75 секунд суммарно без времени загрузок.
- Смешанные типы ошибок одного прохода расходуют один бюджет; новое **полное** прохождение начинает собственный budget. Прерывание вкладки/Debugger либо отмена пользователем не гарантирует восстановление.
- Частичные страницы прежней попытки удаляются; полные предыдущие проходы не теряются. Собственные сетевые API-запросы не выполняются.

## Сравнение завершённых проходов

Дедупликация по message ID, порядок восстанавливается по последовательностям в каждом завершённом проходе. Отсутствовавшие в одном проходе сообщения могут быть добавлены из другого. Конфликт содержимого оставляет исходный ID из первого прохода и предупреждает. Конфликт порядка/ветки выбирает проверенный первый полный проход и предупреждает. Никакой непроверенной последовательности не маркируем успешной.

## Аварийная копия

Только при наличии подтверждённого DOM-tail (плашка лимита, оба последних сообщения извлечены **до** reload), **нуле завершённых проходов** и итоговой ошибке полной истории. Отдельный `.md` содержит исходные последние user + assistant и предупреждение об отсутствии полного контекста. Успешная индикация в панели — только после browser `downloads` completion, иначе отображается ошибка сохранения. Если pre-reload tail нельзя надёжно извлечь, текущая страница не перегружается и оператор получает инструкцию о ручном сохранении.
