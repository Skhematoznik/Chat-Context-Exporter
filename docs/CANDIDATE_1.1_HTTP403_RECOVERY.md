# Кандидат 1.1 — восстановление после HTTP 403

**Статус:** CANDIDATE. Не публиковать в GitHub Releases и не заменять baseline 1.0 без функциональной приемки в Chrome.

## Основание

Диагностический журнал экспорта чата ChatGPT от 2026-10-12 14:05:09 (локальное время): начальный `GET /backend-api/conversations/<id>` вернул `HTTP 200` и корректный JSON (10 обработанных сообщений). Штатный `GET /messages?before=<cursor>` вернул `HTTP 403` с `text/html`. В версии 1.0 это приводило к некорректной для пользователя ошибке «response не является корректным JSON». Полнота истории не достигнута, Markdown не создавался.

## Реализованное поведение

- Диагностика кодов `HTTP >= 400` до чтения и парсинга body.
- Для HTTP 403 **только в активной цепочке ChatGPT authenticated-thread**: ожидание 2500 мс и ровно один reload/retry **для данного прохода**. Другие адаптеры не получают авто-retry.
- Ранее собранные частичные страницы того же прохода сбрасываются при повторе, завершенные проходы сохраняются; если применим, заранее сохраненный authoritative pre-reload DOM tail сохраняется.
- Отдельные диагностические события: `NETWORK_HTTP_ERROR`, `CHATGPT_THREAD_HTTP_403_RETRY_SCHEDULED`, `CHATGPT_THREAD_HTTP_403_RETRY_STARTED`. В событии `PAGE_RELOAD_REQUESTED` теперь фиксируется причина `http-403-recovery` / `normal-pass`.
- При повторном 403 — явная ошибка с HTTP-кодом, без незавершенного `.md`. Другие `HTTP >= 400` завершаются с указанием статуса.
- Во время восстановления запросы к API от расширения не создаются. Используется только browser-level `Page.reload`, который **запускает штатные запросы сайта**.

## Контроль

Тесты: `node --test tests/chatgpt-http-recovery.test.js`.
Проверка исходников: `node --check` для каждого `.js`, JSON-схема `manifest.json`, корректность путей ресурсов, сравнение с baseline 1.0 по разрешенным изменениям. Приемка в реальном Chrome пока **не проводилась**.

## Ручная приемка кандидата

1. Установить кандидат 1.1 отдельной распакованной папкой через `chrome://extensions`; не публиковать как стабильный релиз.
2. В обычном ChatGPT-диалоге с доступной историей проверить успешный экспорт до и после reload, наличие последнего сообщения и сверку количества сообщений.
3. При реальном HTTP 403 проверить появление сообщения о серверном отказе и паузы 2,5 с, только одну повторную перезагрузку **в этом проходе**, успешное восстановление или явное сообщение при повторном 403.
4. При достижении лимита обсуждения убедиться, что pre-reload DOM-tail предыдущего сообщения не теряется и продолжает иметь приоритет.
5. Проверить добровольную отмену во время таймаута, при необходимости приложить технический журнал без приватных данных.

**Ограничение:** перезагрузка не гарантирует, что сервис перестанет возвращать HTTP 403. Нет логики обхода серверной защиты или создания собственных запросов к API.
