# Candidate 1.3.7 — пересечения Stop/reload и стабильность DOM-tail

**Основа:** кандидат 1.3.6. **Статус:** кандидат; браузерная приёмка требуется. Baseline 1.2 не менялся.

## Наблюдения из реального запуска

- Диалог «№ 11 Фреймворк», 2026-10-22 22:14:04–22:14:44 (+03:00), исходный кандидат 1.3.6.
- Первый проход: начальная страница с 10 сообщениями получена с HTTP 200. В 22:14:24, после ожидания Stop, был запрошен restart и страница повторно загружена. Новая начальная страница снова получена с HTTP 200; в 22:14:44 второй Stop перевёл сбор в `generation-unstable` и `ERROR`.
- `CHATGPT_THREAD_START_REACHED` и `PASS_COMPLETED` в журнале отсутствуют. Markdown не сохранён — неполный обязательный проход нельзя выдавать за полный.
- В журнале имеется `SCROLL_UP` в 22:14:24.249, на 140 мс **после** `PAGE_RELOAD_REQUESTED` (22:14:24.109); старый scroll-цикл продолжил работу, пока была запрошена новая загрузка.
- В предоставленном HTML после ошибки видна плашка `role="alert"` с текстом «Вы достигли максимальной длины этого обсуждения...», но ни одной кнопки Stop. Отсутствие кнопки в итоговом снимке не позволяет утверждать, была ли генерация реальной во время предыдущих замеров.
- В начале сессии сохранён authoritative DOM-tail из лимитного чата: `assistantHash=bfe43c42`, `userHash=68d9fe1a` (в журнале). Эти значения используются только для диагностики примера, не зашиты в исходный код.

## Исправления

1. `attemptEpoch` включён в компактный снимок фоновой сессии. Координатор прокрутки запоминает epoch и прекращает движение, если после ожидания Stop текущий epoch изменился, а также при отсутствии актуального курсора. Это предотвращает скроллинг старого документа после команды `Page.reload`.
2. Для **чатов с лимитом длины**, когда до загрузки сохранён авторитетный DOM-tail, после замеченного и закончившегося Stop повторно снимается последний пользовательский и последний ассистентский фрагмент. Продолжение без новой перезагрузки допускается только при совпадении conversation ID, user message ID, turn key, хэшей пользователя/ассистента и длины Markdown ответа. При отсутствии или изменении любого признака действует прежнее консервативное восстановление.
3. Ошибка Stop по-прежнему блокирует перемещение **во время активной генерации**. Полнота истории по курсорам остаётся обязательным условием успешного Markdown-экспорта; HTTP 403/429/500 и checkpoint не изменялись.
4. В worker уточнена передача `reason` при пропуске дополнительного прохода, чтобы диагностическое сообщение «ответ не доставлен» не терялось.
5. Добавлено лог-событие `CHATGPT_GENERATION_LIMIT_TAIL_RECHECK` без текстов сообщений; оно отмечает, совпали ли граничные элементы до и после признака генерации.

## Проверки

- Автоматизированные тесты: см. файл `Chat-Context-Exporter-1.3.7-test-results.tap` рядом с пакетами кандидата.
- Регрессия: неизменённый tail, различающиеся поля, отсутствие плашки, отказ при неопределённости, остановка scroll после смены epoch, прежние обработки HTTP и Markdown.
- Реальный запуск в Chrome с этим же диалогом **ещё не выполнен**.

## Приёмка в Chrome

1. Запустить экспорт «№ 11 Фреймворк» с кандидатом 1.3.7 и включённым дополнительным проходом.
2. Если ChatGPT кратковременно покажет Stop, проверить событие `CHATGPT_GENERATION_LIMIT_TAIL_RECHECK`.
3. Убедиться, что при `unchanged=true` продолжилась пагинация, а не безусловная перезагрузка.
4. Если tail изменился, повтор разрешён ограниченным механизмом, а архив не сохраняется до получения полной курсорной цепочки.
5. При завершении ожидаются `CHATGPT_THREAD_START_REACHED`, `PASS_COMPLETED`, `CAPTURE_READY`, успешное сохранение `.md`.
