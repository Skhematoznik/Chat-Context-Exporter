# Chat Context Exporter 1.3.2 — исправление ложного Stop

## Версия и исходная точка

`CANDIDATE 1.3.2 / STATIC PASS / BROWSER ACCEPTANCE PENDING`.

Исходная версия: кандидат `1.3.1`. Baseline `1.2` и публикация GitHub не изменяются.

## Фактическая причина

В представленном пользователем HTML страницы `№ 8 AWF` обнаружены две кнопки `aria-label="Остановить"` в неактивных копиях composer. Обе расположены внутри предков `style="display: none;"` и `display: none !important`. Проверка 1.3.1 исключала только `hidden`, `aria-hidden` и disabled; поэтому трактовала скрытые Stop как признак генерации. Журнал `21:42:19` подтверждает срабатывание `CHATGPT_GENERATION_ACTIVE` до первого прохода и отмену спустя 26 секунд.

## Исправление

`src/adapters/chatgpt/generation-guard.js`:

- дополнительно проверяется `getClientRects()` с ненулевой геометрией, исключая любые предки `display:none`;
- исключаются невидимые состояния `visibility:hidden/collapse`;
- исключаются `inert` и отсоединенные от документа элементы;
- сохраняются прежние точные имена Stop и проверка `aria-hidden`/`hidden`/disabled.

Никакие кнопки ChatGPT не нажимаются. Ожидание реальной генерации перед первым проходом, после reload и перед прокруткой сохранено. Без изменений оставлены UI-панель из 1.3.1, 403/429 recovery и checkpoint, пагинация и Markdown.

## Локальные тесты

`node --test tests/*.test.js` — **69/69 PASS**. Синтаксис JavaScript — PASS. Запрещено считать реальный Chrome подтверждённым до браузерной приемки. Регрессия включает две скрытые Stop из приложенного HTML и видимый Stop, который по-прежнему должен блокировать сбор до завершения ответа.

## Приёмка Chrome

1. Запустить экспорт на `№ 8 AWF`, где нет видимой кнопки Stop, и подтвердить `CHATGPT_GENERATION_GUARD_PASSED | phase=before-start` до начала сбора.
2. Во время реальной генерации подтвердить ожидание, без преждевременной прокрутки.
3. После загрузки и на дополнительном проходе проверить раннее восстановление плавающей панели и всю цепочку пагинации.
4. При возможной ошибке 429 отдельно проверить checkpoint; отсутствие такой ошибки в данном запуске не подтверждает работающий путь восстановления.
