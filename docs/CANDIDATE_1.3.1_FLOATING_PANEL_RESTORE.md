# Chat Context Exporter 1.3.1 — ускоренное восстановление плавающей панели

## Статус

`CANDIDATE 1.3.1 / STATIC TESTS PASS / BROWSER ACCEPTANCE PENDING`.
Исходная точка — кандидат 1.3 на основе стабильного baseline 1.2. Это UI-патч, не повышение baseline.

## Наблюдение

В журнале `№ 8 AWF` от 18.10.2026, 21:13:59 (+03) экспорт 1.3 завершился; после `PAGE_RELOAD_REQUESTED` загрузка страницы занимала заметное время, и плавающая панель в этот период исчезала. Пользователь выбрал **только плавающую панель, без Chrome Side Panel**.

## Причина

Обычная панель реализована как DOM-элемент `#chat-context-exporter-ui`. При `Page.reload` старый документ уничтожается вместе с DOM-панелью. Фоновая сессия `captureSessions` при этом не уничтожается. В 1.3 полный набор content scripts внедрялся при `chrome.tabs.onUpdated` только с `status=complete`, из-за чего во время загрузки не было визуального подтверждения работы.

## Изменения

1. `src/content/early-panel.js`: отдельный компактный плавающий индикатор без зависимостей от адаптеров или DOM ChatGPT; запускается в `ISOLATED`-контексте, когда доступен `document.documentElement`. Сохраняет существующий ID панели и не дублируется при повторном внедрении.
2. `src/background/service-worker.js`: событие `loading` запускает best-effort внедрение c `injectImmediately`; ограниченные попытки после 0, 350 и 1400 мс, поскольку ранняя инъекция может быть отклонена или попасть в старый документ до commit. `complete` по-прежнему загружает полный runtime.
3. Во время `loading` `notifyCaptureSession` не внедряет полный runtime досрочно, чтобы не запускать адаптеры до готовности DOM.
4. `GET_STATE(summaryOnly=true)`: передаёт состояние без массива технических событий и без полного набора сетевых захватов. Индикатор использует данные о фазе, проходе, страницах, сообщениях, времени старта и HTTP 429. Проверяется соответствие ожидаемого conversation ID текущему URL.
5. `manifest.json`, `src/core/namespace.js`, тестовые проверки версии и документация синхронизированы с `1.3.1`.

В механизмы пассивного чтения штатных ответов, HTTP 403/429, ограничение повторов, checkpoint, проверку Stop, прокрутку и экспорт Markdown изменения не вносились. Разрешения Chrome не увеличены.

## Локальные тесты

`node --test tests/*.test.js` — 65/65 PASS, включая новые тесты раннего внедрения при `loading`, повторных попыток, подавления преждевременного полного runtime, компактной выдачи состояния и отображения HTTP 429.

## Браузерная приёмка

1. Установить кандидат в `chrome://extensions` и открыть большой ChatGPT-диалог.
2. Запустить экспорт и наблюдать за **первой** штатной перезагрузкой: проверить, что компактная плавающая панель появляется раньше полной загрузки ChatGPT. Зафиксировать интервал без панели, если он есть.
3. Убедиться, что компактный индикатор превращается в обычную панель без дублей, не начинается вторая сессия и не увеличивается число сетевых запросов ChatGPT.
4. При включённом дополнительном проходе проверить повторное появление панели на следующем reload и сохранение времени с начала сессии.
5. По возможности проверить HTTP 429 с паузой: статус ожидания показывается и после reload; штатный checkpoint сохраняется.
6. После окончания проверить отсутствие расхождений Markdown и полный технический лог.

**Физическое ограничение:** плавающая DOM-панель не может пережить уничтожение HTML-документа или отображаться поверх встроенной пустой страницы Chrome. Стратегия best-effort ускоряет восстановление, но **не гарантирует непрерывное присутствие**. Полная браузерная приёмка до появления такого отчёта не заявляется.
